# Liquid 로컬 사과 관측 실험

2026-09-25, 실제 실행 완료. **저비용 시각 특징 추출 후보로는 사용 가능하다. 이번 설정에서 행동 선택과 미해결 기억 처리를 모델 단독으로 맡기는 것은 부적합했다.**

사용자 결정으로 현재 프로젝트는 **토마토 + Liquid 저비용 관측 + GPT-5 정밀 분석**을 채택했다. 이 보고서의 측정값은 기존 **사과 4장 실험**이며 토마토 성능 결과로 해석하지 않는다. 활성 설계는 [final_plan.md](../final_plan.md)를 따른다.

## 실행 환경

- Mac Apple M5, RAM 16 GiB, macOS 26.5.1, llama.cpp Metal 장치 `MTL0` 확인.
- `LiquidAI/LFM2.5-VL-1.6B-GGUF`: `Q4_K_M` 본체 + `Q8_0` 비전 projector.
- 가중치 합계 1,314,006,144 bytes, 약 1.31 GB. 다운로드와 런타임은 이 폴더에만 설치.
- llama.cpp `b11191`, 모델 revision `36fc16bc95133424921bcc3da009e83b2f23ffb5` 고정. 공식 배포 체크섬 검증 완료: [installation.json](installation.json).
- `.env`를 읽지 않았고 외부 추론 API를 호출하지 않았다. 모델·이미지 다운로드에는 인터넷을 사용했다.
- 실행 서버는 `127.0.0.1:18081`로 제한하고 각 실험 종료 시 종료했다.

## 데이터와 방법

[Mendeley 사과 데이터셋](https://data.mendeley.com/datasets/y7gktb2wwb/1)의 원본 `healthy` 2장, `infected` 2장. 기존 Nimble 검색 카탈로그에서 발견한 자료다. 파일명 사전순으로 클래스별 첫 2장을 선택했고 모델 결과에 따라 재선별하지 않았다. CC BY 4.0, 저자·라이선스·SHA256은 [input_manifest.json](input_manifest.json)에 기록했다.

각 설정에서 4장 × 2회 = 8회 측정했다. 설정별 별도의 워밍업 1회와 텍스트 기억 검사 2회를 포함하여 전체 호출은 **33회**다. 입력 라벨과 파일명은 모델에 전달하지 않았다. 온도 0, seed 42, 출력 상한 160, context 4096, 병렬 슬롯 1, 요청 캐시 비활성화. `json_object`로 JSON 문법을 제약했지만 필드와 행동 의미는 별도 검사했다.

기억 검사는 같은 사진에 각각 “이전 의심이 미해결이며 정밀 분석 시점이 됨”과 “이전 의심 해결됨”이라는 텍스트를 주는 지시 이행 검사다. 실제 시계열·DB 저장·재시작 복원 실험은 아니다.

## 측정 결과

| 입력 | image-max-tokens 설정 | 요청 시간 중앙값 | 시간 범위 | 관측된 최대 서버 RSS | 전체 prompt tokens |
|---|---:|---:|---:|---:|---:|
| 원본 | 64 | 6.45초 | 6.26–13.41초 | 1.51 GiB | 1,749 |
| 원본 | 256 | 6.95초 | 6.51–7.36초 | 1.54 GiB | 1,929 |
| 최대 변 512px | 256 | **2.19초** | 1.48–3.22초 | **1.33 GiB** | **344** |

시간은 서버 준비 후 클라이언트가 요청 전송부터 응답 수신까지 측정한 값이며, 워밍업·기억 검사는 중앙값에서 제외했다. 512px 리사이즈 시간과 서버 시작 시간도 제외했다. 서버 준비 시간은 첫 실행 17.76초, 후속 실행 1.02초·3.59초였다. 전용 벤치마크 기기가 아닌 사용 중인 노트북이며 백그라운드 작업을 통제하지 않았다. 첫 원본 실행 중 장치 조회도 수행하여 느린 응답의 원인을 단정할 수 없다.

RSS는 `ps`로 0.2초 간격 샘플링한 서버 프로세스 값이며 전체 시스템·Metal 통합 메모리 사용량을 뜻하지 않는다. 입력 토큰 수는 이미지·지시문·특수 토큰을 모두 포함한다.

같은 256 설정에서 축소 입력의 중앙값은 원본보다 약 3.17배 빨랐다. **이것은 해당 네 장의 입력 처리 비교이며 API 비용 절감률이나 일반 처리량 보장이 아니다.**

`--image-max-tokens`는 이 모델에서 타일을 포함한 최종 토큰 수의 절대 상한으로 해석할 수 없다. 큰 사진은 512px 타일들과 축소 전체 사진으로 나뉜다. 따라서 설정값만 낮추는 것보다 실제 입력을 축소한 효과가 컸다. [고정 버전 전처리 구현](https://github.com/ggml-org/llama.cpp/blob/b11191/tools/mtmd/mtmd-image.cpp#L860-L917).

## 판단 품질과 발견된 실패

- 모든 설정에서 네 장의 `visible_anomaly` 출력은 원본 정상/손상 라벨과 일치했다. 설정당 8회 반복 중 8회이며, **독립 표본 8개 또는 일반 정확도 100%라는 뜻은 아니다.**
- 원본 입력은 손상이라고 설명하면서도 `routine_observation` 또는 `retake_photo`를 선택했다. 두 설정 모두 손상 사진의 4회 호출 중 `strong_analysis` 선택은 0회였다.
- 512px 입력은 손상 사진 4회 중 2회만 `strong_analysis`를 골랐다. 나머지는 재촬영을 선택했다.
- **미해결 기억 + 정밀 분석 기한 도래 검사에서는 세 설정 모두 정밀 분석으로 넘기지 않았다.**
- 전체 33회 중 32회는 요구 필드를 만족했다. 원본 256의 기억 해결 검사 1회는 `next_action` 필드가 없었다. JSON 문법 보장과 출력 계약 이행은 다르다.
- 일부 설명은 RGB만으로 검증할 수 없는 내부 부패 가능성까지 추측했다. 설명을 진단 사실로 저장하면 안 된다.

원본 응답과 실행 로그: [원본 입력 실행](results/20260925T213840Z/summary.json), [512px 실행](results/20260925T214154Z/summary.json), [비교·규칙 재생 결과](results/comparison.json).

## 우리 아키텍처에서의 사용 제안

`가벼운 변화 검사 → Liquid(512px)로 이상 후보 추출 → 외부 기억과 규칙으로 행동 결정 → 필요하면 GPT-5에 원본·과거 근거 전달`

Liquid의 `next_action`을 그대로 신뢰하지 않는다. [routing.py](routing.py)는 다음 규칙을 구현한 실험용 보호 계층이다.

1. 외부 기억에 미해결 의심 또는 재검토 기한이 있으면 정밀 분석한다.
2. `visible_anomaly=yes/uncertain`이면 정밀 분석한다.
3. 출력이 불완전하면 정밀 분석한다. 재촬영 제안은 별도 처리한다.
4. 이상이 없고 미완료 과제가 없으면 일상 관측을 이어간다. 정상 확진이나 `SKIP` 판정으로 해석하지 않는다.

저장된 출력에 이 규칙을 재생했을 때 모든 손상 후보와 미해결 기억이 정밀 분석 경로로 전달됐다. 이는 **코드 분기 검사**이며 실제 GPT-5 분석 또는 종단간 정확도 검증은 아니다. 작은 모델이 이상 자체를 놓치면 이 규칙도 해결하지 못하므로 초기 관측·최대 무분석 시간 등의 별도 재검토 조건이 필요하다.

## 비용과 검증 범위

이 실험의 추론 API 청구액은 **$0**이다. 전력, 기기 점유, 유지보수 비용은 미측정이다. GPT-4.1-mini보다 전체 운영 비용이나 지연이 낮다고 아직 결론 내릴 수 없다.

4장은 큰 손상이 드러난 정적 사진이고 클래스별 배경이 다르며, 실제 독립 개체 수도 불명확하다. 512px에서 미세한 초기 병변이 사라질 수 있다. 질병 진단, 조기 탐지, 동일 사과 변화 비교, long-horizon 비용 절감은 검증하지 않았다.

다음 검증은 동일 토마토 시계열에서 Liquid 관측과 외부 Controller를 GPT-5 정밀 분석에 연결하여 수행한다. 정밀 분석 호출 비율뿐 아니라 미탐·오탐·탐지 지연, 각 모델별 토큰·API 비용, 로컬 실행 시간을 함께 측정한다.

## 재실행

프로젝트 루트에서 실행한다. Python 표준 라이브러리와 macOS 기본 `sips`를 사용한다.

```bash
# 설치 파일이 없을 때만 필요. 기존 파일도 체크섬 재검증.
python3 liquid/setup.py

# 이번 권장 후보 설정: 4장 각각 2회 + 워밍업/기억 검사
python3 liquid/benchmark.py --resize 512 --budgets 256

# 원본 입력 비교
python3 liquid/benchmark.py --budgets 64 256

# 결과 재집계 및 실제 발견된 분기 오류 회귀 검사
python3 liquid/summarize.py
python3 -m unittest discover -s liquid -p 'test_*.py'
```

원본 4장은 `inputs/`에 있으며, 대용량 모델·런타임·이미지는 Git에서 제외했다. 새 컴퓨터에서는 manifest의 데이터셋 ZIP 내부 경로에 해당하는 네 파일을 준비해야 한다. 모델 및 데이터 라이선스는 각각 다르다.
